# CPU ↔ DDR 指针跨时钟：给哪 120 个触发器加属性？

四路 BOOM 的物理候选中，CPU 和 MIG UI 时钟之间有五个 AXI 通道。每个通道的读、写指针各有四位，每位在另一时钟域经过三级触发器。旧版整机布线报告把这 40 条指针路径列为 `CDC-2`。本实验问的是：**如果仅对这些接收触发器声明 `ASYNC_REG`，Vivado 是否只对预期的路径改变分类？** 它不测吞吐，也不替代整机的复位、时序和约束审查。

### 同一份综合网表，三次报告

从原版和恢复版两份封存输入核对了 20 个 crossing/queue 模块及两个父模块，并逐一比对父模块间 246 个异步字段。独立顶层保留所有 AXI 业务端口，使用真实的双向队列；没有实例化 CPU、MIG PHY 或板级时钟树。器件为 `xcvu9p-flga2104-2L-e`，Vivado 2024.2 以 OOC 模式综合；实验时钟分别为 5.714 ns 和 5.000 ns，两域设为异步。

| 同一网表的状态 | 目标 `CDC-2`（告警） | 目标 `CDC-3`（信息） | 其他路径 |
|---|---:|---:|---|
| 未添加属性 | 40 | 0 | 266 条 |
| 仅标记 120 个接收触发器 | 0 | 40 | 逐条不变 |
| 仅撤销 AW 写指针第 0 位的三级属性 | 1 | 39 | 逐条不变 |

未变的 266 条中，264 条是 `CDC-15`，两条 `CDC-2` 是 AW 队列的有效标志通路。它们没有被豁免。局部报告不包含整机的六条 Critical，不能把它们从整机问题单上划掉。`CDC-3` 仅表示工具识别到同步结构，不能证明布局相邻、总线偏斜达标、亚稳态失效率或队列复位协议正确。

脚本先核对每条首级 D 的唯一 Q 驱动，再核对 120 个接收 FDCE 的时钟、链内复位网以及 80 条级间连线的唯一负载；最后比较整份网表中带属性的原语集合。局部综合时 40 个发送端中有 10 个寄存器名不同于旧版布线设计，恰好是每个指针的最高位。只对 bit 3 接受同一队列的二进制指针最高位：十个发送队列的真实 RTL 均从同一个下一计数值更新 Gray 和二进制最高位，且在同一 always 块异步清零。其余位、其他队列的同名寄存器都不接受。

### 复现与整机接入边界

1. `python -B scripts/test-mega-gray-attributes.py STOCK_KIT RECOVERY_KIT BITS_TSV OLD_ROUTED_CDC INPUT_DIR`：两个 kit、旧版逐位表和旧版路由报告必须是记录中的确切版本。创建独立的全新私有输入目录。
2. `vivado -mode batch -source scripts/probe-mega-gray-attributes.tcl -tclargs INPUT_DIR NEW_OUTPUT_DIR`：查退出码为 0，且单独出现 `VCU_GRAY_ATTR_EXPERIMENT_FINISHED_NOT_SIGNOFF`。
3. 第一步命令追加 `--review NEW_OUTPUT_DIR`：验证同一运行的原生报告、两端时钟、所有端点、规则、同步深度与时序例外，并对五种受损记录做反证。[去敏结果和指纹](perf-mega175-gray-attributes.json)不包含原始工具日志、生成 RTL 或 DCP。

[定向属性脚本](../scripts/annotate-mega-gray-pointers.tcl)另有 `board` 入口，供**以后独立封存并重新实现**的候选在综合后、优化前调用；此次只验证了 `probe` 入口，未修改在跑的整机构建。整机必须重新检查准确的层级、综合态时钟以及布线后的同步链位置、指针偏斜/数据延迟、复位通路、全量 CDC/DRC 和时序。不得用局部报告替代以上检查或批准上板。
