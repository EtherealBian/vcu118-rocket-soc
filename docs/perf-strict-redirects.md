# 四路 BOOM 的分支恢复：哪条指令真的重新取了？

**性能种子中，2,514 次后端重定向能追到最终退休的热区指令，其中 1,541 次在链表函数 `core_bench_list`（61.3%）。** 两种种子中，触发重定向最多的都是这个函数里的同一条比较指令。本次是四路 BOOM 对 Linux 用户程序快照的 RTL 重放，外部内存为行为模型，不是上板跑分。

| 同一 ELF、单 hart、每种种子四轮 | 性能种子 | 验证种子 |
|---|---:|---:|
| U 态观察到的 B2；其中未与热区退休相配 | 2,599；85 | 2,733；109 |
| 热区条件分支：匹配 B2 / 退休总数 | 2,514 / 212,745（1.18%） | 2,624 / 213,495（1.23%） |
| 间接跳转：匹配 B2 / 退休总数 | 0 / 4,988 | 0 / 4,928 |
| 按动态分支退休所在轮，第 1 / 2 / 3 / 4 轮匹配数 | 1124 / 553 / 460 / 377 | 1191 / 599 / 458 / 376 |
| B2 → 下一条正确路径指令派发，P50 / P95（拍） | 6 / 6 | 6 / 6 |
| B2 → 下一条正确路径指令退休，P50 / P95（拍） | 11 / 31 | 11 / 32 |

这里的分母是**该种子热区内实际退休的条件分支**。分子只数后端 B2 发出、前端 S0 选中、下一拍 S1 收到，而且同一条动态分支最终退休的重定向。它不是所有前端修正的总和，也不是某一层预测表的命中率。窗口外或投机路径上未能与热区退休票据匹配的事件单独留账，不认定每条都被冲刷。

## 该优化哪里？

性能种子中次数最多的是 `core_bench_list` 中的 `0x13eda`：`bge x6,x28,0x13f3a`。两边比较值分别来自两次半字加载；不能仅凭 PC 就断定在等内存。该指令退休 830 次，其中跳转 504 次，带 B2 重定向 325 次（跳转 104、不跳 221）。验证种子同一处分支退休 837 次，其中 308 次带 B2。按全窗口汇总，性能种子第四轮只有 377 次匹配重定向，区别于第一轮的 1,124 次；不能把冷启动的结果当稳态。

可做的工程选择：**保留现有预测器和四路物理主线**。若要改分支恢复，先定位链表比较操作数何时就绪、B2 发出后正确路径何时首次派发；在同一份未改的 ELF 上比较总周期和分轮周期。既有[同沿分支掩码译码备选](perf-mega175-branch-mask.md)改的是逻辑深度，不会凭空减少这里统计的误判次数；是否值得换用，要看原版的布线后慢路径。

后续[两个加载值到分支 ALU 的逐次核对](perf-strict-load-use.md)已补上这段时间线，区分了加载结果到达、实际比较和注册 B1。

## 怎样防止把错误路径算入成绩？

1. 使用[封存的四路原版和相同快照](perf-strict-user-lvt.json)，只重链接观测程序，不换 RTL。每个实际派发槽记录 `(派发沿, ROB 行×4+槽)`。只靠静态 PC 会把同一循环的不同迭代混在一起，只靠 ROB 槽则会在回绕后指错指令。
2. 观察 `b2_mispredict`，排除有更高优先级 flush 的周期，核对前端实际选择和下一拍 S1；在四路 ROB 提交端重建有序 PC。按票据关联后，逐条核对源 PC、指令长度、控制流类型和实际下一条退休 PC；条件分支还按 ELF 机器码解出立即数，并独立核对每次退休的真实方向。引用的符号及指令地址都属于公开实验清单锁定的基准 ELF。
3. 两个种子的有序 PC、UART 结果、分轮边界和周期、完整事件日志的摘要均与[没有探针的原版](perf-strict-user-replay.md)一致；有序 PC 另与独立 QEMU 对照一致。各从实际捕获选一条已匹配记录，仅翻转源地址或仅翻转目标地址的第 1 位，四项篡改均被复核脚本拒绝。
4. 表中延迟用最近秩分位数，起点是实际发出 B2 的沿，终点是动态分支的**下一条正确路径指令**派发或退休的沿。退休还可能等待更老的指令；多次恢复也可能重叠。**不能用重定向数乘以中位延迟推算可省周期，更不能把 6 拍或 11 拍称作 CPU 的流水级数。**

另做了两个低成本**离线方向预测**对照，输入是完全相同、带实际方向的退休条件分支流。第一个有 1,024 个 2 位计数器，以半字 PC 低 10 位索引；第二个以半字 PC 低 8 位查 256 项 4 位局部历史，再把低 6 位 PC 与 4 位历史拼为 1,024 项计数器索引。按程序顺序先预测再更新；每个种子从弱不跳和全零历史开始，轮间不清空。它们不建模目标预测、前端二次修正、推测历史或更新时序，因此只列方向错误，不与 B2 比值换算 IPC，也不冒充替换预测器后的整核实验。

| 1,024 项双模态计数器 | 4010 / 3967 / 3970 / 3957 | 4016 / 3945 / 3967 / 3954 |

## 离线复核

原始捕获、ELF、模型与生成的 RTL 只在本地使用。以下命令需要此前封存的 stock kit、模型对象、两份 guest 快照、Verilator 头文件及对应 RISC-V objdump；输出目录须尚不存在。公开的[汇总 JSON](perf-strict-redirects.json)包含原始捕获的散列与逐热点分布，不包含逐条执行轨迹。

```sh
python3 scripts/test-strict-redirects.py "$STOCK_KIT" "$STOCK_OBJ" "$GUEST" "$PRIVATE/b2" "$VERILATOR_INCLUDE"
python3 scripts/review-strict-redirects.py "$PRIVATE/b2" "$ELF" "$OBJDUMP" > "$PRIVATE/b2-review.json"
cmp "$PRIVATE/b2-review.json" docs/perf-strict-redirects.json
```
