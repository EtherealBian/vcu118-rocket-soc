# 四路 BOOM：取指地址要等 64 位历史比较完成吗？

旧版[完整布线路径](perf-mega175-routed-recovery.md)中，循环预测器到 I-cache 地址的建立余量为 −9.230 ns。详细路径经过预测历史位、比较逻辑和一个扇出 154 的网络，之后还有两次跨 SLR；物理网名不能单独证明每个 LUT 对应哪一行 RTL。上一次改的是[循环预测器本身](perf-mega175-loop-repair.md)。这次检查同一前端的另一段：`BoomFrontend` 如何比较 F3 的预测历史和 F1/F2 保存的历史，决定是修正取指地址还是沿用原路径。

**当前正在综合的封存物理版没有被修改。** 以下从它的 `BoomFrontend.sv` 派生，都是同周期组合改写，没有添加流水级、改预测策略或更改约束。这些实验的目的是挑选下一次局部布线的候选，不是报告 Fmax 或 Linux 跑分。

## 两种缩短等待的办法

- **历史先比较。** 一次比较基础历史，一次比较额外移入零后的历史，待分支方向确定后只选一位相等结果。之所以只有两个备选，是因为第一组有控制流重定向时，原逻辑一定忽略第二组；不存在既不忽略第二组，又因第一组的已选分支而再移入一的二态条件。实际写回的历史及方向标记仍须匹配。
- **四条一组判断方向。** 不再为了统计跳转前的分支，先把最早重定向位置编码成索引、再把索引解回掩码。一个版本在两组各自做前缀判断；另一个直接用原版已判定有效的 lane 掩码与预测方向。后一种写法不能用未屏蔽的解码结果：较早指令跳转后，有分支编码不等于这条指令仍然有效。

## 同一逻辑边界的结果

从原版和每个派生的**实际 RTL 声明**追踪 82 个输出位，包括两级历史比较、预测历史、F3 校正选择（`_GEN_133` 是 `s0_vpc` 使用的判定）、F2 清除信号、控制流索引/有效位和分支掩码。556 个二态输入位包含真实 8 路预测方向、10 个解码器输出以及取指数据、掩码与历次历史。真实的压缩指令边界、各 lane 的有效性、跳转优先级保留；F3 目标地址作为 40 位输入，不包含其产生器，也不包含 I-cache BRAM。没有对方向、解码或掩码添加 one-hot 假设。

| 写法 | 8 路预测方向 → F1 / F2 历史比较（层） | → F3 校正选择 / F2 清除（层） | 该逻辑边界内组合原语数 |
|---|---:|---:|---:|
| 原版 | 24 / 24 | 26 / 27 | 1,232 |
| 仅历史先比较 | 18 / 18 | 20 / 20 | 568 |
| 仅两组前缀 | 17 / 17 | 18 / 19 | 588 |
| **两组前缀 + 历史先比较** | **14 / 14** | **15 / 16** | 677 |
| **仅用有效 lane** | **16 / 17** | **18 / 18** | **555** |
| 有效 lane + 历史先比较 | 16 / 16 | 17 / 18 | 681 |

每个数字来自同一 Yosys/ABC `xcup` 未布局映射，层数按相应输入到输出最长组合原语链计，原语总数包括 LUT 和 MUXF，**不是**占用的 LUT 站点，也不是 ns。各输出共用逻辑；改变观察边界会改变映射，不能把这些层数从旧版整机路径中直接减去。例：最快校正候选的控制流索引有效位为 11 层，原版为 10 层。面积候选对应端点为 14 层，也有代价。

- [二态证明与全部映射](perf-mega175-f3-history.json)：五种写法均证明 82 个输出位与原版相同。四种故意错误（放开 lane 2 掩码、漏记 lane 3 非跳转分支、忽略 PC 边界、混接 F1/F2 历史）分别得到反例。
- [父模块交叉检查](perf-mega175-f3-history-parent.json)：在 Vivado 2024.2 XSim 中使用**未提取的完整父模块文本**，分别实例化原版和表中两种粗体候选。在固定时钟、子模块接口桩和受控输入上观察 3,072 组二态激励，122 位（上述 82 位加实际 `s0_vpc` 的 40 位）逐组相同，原版这些位无未知值。八个 lane 均被选中过，八种 PC 分组均出现，F1/F2 各自 64 个历史位均注入过差异。两条地址不同时，观察到 472 次选 F3、102 次选测试设定的 S2 备选。未屏蔽 lane 2 的错误版本在 44 个样本与原版不同。这里没有推进时钟，不是完整处理器或指令缓存的时序功能仿真。

**决策：保留原版、最快校正候选、最少原语候选三者作同约束物理对照。** 是否集成取决于布线后的选择、清除、索引/历史等并行端点及全局最差路径，不因局部层数下降重启现有整机实现。

## 复现

`KIT` 为 SHA-256 `ce0ef1171c7b0077282602c5c97230d03850b71c350c6c9ddcdf0b7ebcb5a456` 的物理输入包；`PROOF`、`PARENT` 为两个不存在的新目录。第一步用配套的 Yosys 0.9 和 `berkeley-abc`（后者在 PATH 中），第二步使用 Vivado 2024.2。只发布自写脚本与去敏记录，不分发生成的厂商源。

```sh
python3 scripts/test-mega-f3-history-compare.py "$KIT" "$PROOF" --yosys "$YOSYS"
python3 scripts/test-mega-f3-history-parent.py "$KIT" "$PROOF" "$VIVADO_INSTALL" "$PARENT"
```
