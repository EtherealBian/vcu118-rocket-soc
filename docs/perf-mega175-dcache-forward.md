# D-cache 第二条访存通道：把地址比较提前一拍

归档四路 BOOM 的同一份布线端点表里，`s2_req_1_addr[19]` 到整数寄存器堆有五条路径，裕量为 −9.207 至 −9.177 ns，跨 32–33 级逻辑。报告给出了起终点，没有给这五条路径的逐段延时。因此这里分别检查两条在 RTL 中确实使用地址位 19 的分支，不预设哪一条在布线上最慢。

**存储转发。** lane 1 的加载先查同一 8 字节字地址是否有更新的写入，按 S3、S4、S5 的顺序选择；都未命中则使用 cache 数据。三组 37 位比较的两侧地址都来自同一上升沿、无使能的寄存器。候选在该沿用这些寄存器真正的 D 输入计算相等性，锁存 **3 个匹配位**；有效位、数据、优先级和响应拍数不变。未改 lane 0 或其 AMO 路径。代价是比较逻辑和相应扇出移到了前一拍；本实验没有证明这笔交换能改善整机时序。

| 检查 | 边界及结果 |
|---|---|
| 二态 SAT | 从实际新旧父模块抽取，一次上升沿前四个 40 位地址独立任取，沿后三个有效位及四个 64 位数据字任取；两个版本的 64 位转发结果相等。不约束上电初态，也不对第一个沿之前的输出作保证。 |
| 错误设计负控 | 错用晚一拍的存储地址、误用字节偏移、漏比地址位 19、对调 S3/S4 匹配位，四个变种都得到反例。 |
| Vivado 2024.2 XSim | 对两个实际父模块逐拍比较，13 类直接子模块只保留端口，在明确的内部输入处驱动。724 个时钟沿；64 种地址匹配/有效掩码组合、37 位 × 3 个存储级的单比特不匹配、6 个含 X 的定向样例。已检查转发字和缓存加载响应数据；不等于完整 cache 事务。 |

**缺失请求跟踪表（MSHR）是另一条分支。** 父模块仍把完整的 lane 1 地址交给 `BoomMSHRFile`。对其真实 `io_block_hit_1` 逻辑做单独的 SAT 检查：在给定的槽位状态边界，任取基地址，8 个槽中的任一个作为唯一有效、匹配的槽，仅翻转请求地址位 19 就会让这个输出从 1 变为 0。这个输出返回 D-cache 的命中判定。因此不能把存储转发的改写理解为消除了该地址位的所有同拍依赖，更不能据此豁免路径。此证明不声称每个槽位边界组合在每笔事务中都可达。

候选仅在独立目录派生，**未加入正在综合的整机**。取到设计的逐段时序后，再决定应优化转发、MSHR 匹配还是其它逻辑。若纳入后续构建，还需真实复位启动、整核回归和同版实现审查。没有产生 MHz 或 CoreMark 实测值。
