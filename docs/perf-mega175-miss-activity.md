# 四路 BOOM：加载失败信号何时改变整数发射队列？

这次把两个问题分开验证：**恢复版运行 CoreMark 时，有多少拍真的用到这条信号？原版布线中，延时发生在信号分叉之前还是之后？** 两份证据来自不同构建，不能据此推算恢复版频率或板上跑分。

## 恢复版：逐拍核对 39 个目的槽

对[同版 ChipTop 与同一严格 ELF](perf-mega175-recovery-fullcore.json)的性能、验证两个用户态快照各回放四轮。只读观察器在上升沿前，按 40 个驻留槽的状态、发射许可、就绪位以及推测唤醒标记重建搬移选择。对每个目的槽分别计算 `miss=0` 和 `miss=1` 的值，再用当拍 LSU 信号选择，逐位核对 DUT 的实际搬入有效位。槽 39 只接收分发输入，不计入这 39 个目的槽。两种子的退休 PC 轨迹、UART 输出、事件记录和每轮边界均与未加观察器的归档一致。

| 四轮用户态窗口 | 性能种子 | 验证种子 |
|---|---:|---:|
| 采样拍数 | 653,447 | 657,536 |
| LSU 推测加载失败信号为 1（拍） | 4,128 | 4,135 |
| 至少一处搬入对 miss 敏感（拍） | 104,607 | 105,880 |
| 实际 miss 改变至少一处搬入（拍） | 1,835 | 1,645 |
| 上述实际变化累计涉及的目的槽样本 | 2,756 | 2,742 |
| 槽 8 的搬入对 miss 敏感（拍） | 3,678 | 4,006 |
| 其中实际 miss 改变槽 8 搬入（拍） | 20 | 26 |
| 槽 8 实际变化来自槽 9 / 10 / 11 / 12（拍） | 1 / 0 / 0 / 19 | 2 / 0 / 0 / 24 |

“敏感”指其余输入固定时，两种 `miss` 取值会给出不同结果；“实际”还要求当拍 DUT 的 `io_core_ld_miss=1`。一个实际拍可涉及多个目的槽。这里统计的是**推测加载失败对搬入选择的作用**，不是 L1 缓存失效次数、损失的周期数或整个 `p2` 寄存器时序路径的激活次数；不据此设置 false path。[逐轮、逐槽及输入指纹](perf-mega175-miss-activity.json)。

## 原版：八条有逐引脚数据的慢路径分成两组

在同一份原版布线后、物理优化前的检查点里，按原始延时、原语引脚和走线逐段比对；40 个端点中只有前八条有详细报告。

| 起点及排名 | 共同走线段数 | 共同走线增量之和 | 从启动触发器至分叉驱动端的数据延时 | 从分叉驱动端至终点的数据延时 |
|---|---:|---:|---:|---:|
| 分支状态经 LSU，#1、#8 | 22 | 6.018 ns | 7.961 ns | 6.764 / 6.737 ns |
| 取指 F3 循环预测计数，#2–#7 | 21 | 5.731 ns | 7.816 ns | 6.582–7.169 ns |

LSU 的同一条扇出 122 的网分别跨 SLR1→2，至两个首个接收引脚的增量为 1.640 / 1.920 ns，最终到整数槽 8 / 4。F3 是另一条路径，分叉后到四个 I-cache 终点及两个预测器终点。两组**仅到分叉点**的数据延时都已超过请求的 5.714 ns 周期，不能指望保留旧版这段走线、只优化末端就解决问题。这些数据延时不是建立余量，也不代表新版结果。[八条逐路径数据](perf-mega175-route-forks.json)。

## 取舍：暂不合入 LSU 响应选择改写

对恢复版的两条 LSU 通路尝试提前分别计算转发成功与响应成功，保留响应优先和 store/AMO 行为，不加流水级。在队列读取之后截取实际表达式，对 63 个自由二态输入做 SAT 等价验证；故意破坏响应优先级、跨通路错接标签或忽略 store 响应时均得到反例。通用 6 输入 LUT 映射中，一路响应有效位到输出的深度从 4 降到 3，但另一路仍为 4，整体最深仍为 4，LUT 从 21 增到 22。没有证明全局时序收益，**不修改在跑的物理版**。此比较未做器件布局布线。[等价证明、工具指纹、映射结果](perf-mega175-lsu-miss-fork.json)。

## 复核

在具有对应私有输入的工作区中执行；变量分别指向封存的物理包、模型包、先前已验证的对象目录、快照、严格 ELF、Verilator 安装、输出目录，以及原版 DCP/报告、Yosys 可执行文件。每个 `run` 使用新的外部目录；映射需要 Yosys 对应的 `berkeley-abc` 在 PATH 上。公开文件不含 DCP、生成的 RTL、原始捕获或本机路径。

```sh
python3 scripts/test-mega-miss-activity.py run "$PHYSICAL" "$KIT" "$PREVIOUS" "$GUEST" "$ELF" "$VERILATOR" "$OUT"
python3 scripts/test-mega-miss-activity.py review "$PHYSICAL" "$KIT" "$PREVIOUS" "$GUEST" "$ELF" "$VERILATOR" "$OUT"
python3 scripts/review-mega-route-forks.py "$OLD_DCP" "$OLD_REPORTS"
python3 scripts/test-mega-lsu-miss-fork.py "$PHYSICAL" "$YOSYS" "$CONE_OUT"
```

本实验不验证 DDR、时钟约束、板上引导或 Linux CoreMark 每秒迭代数。是否可以上板，仍取决于恢复版自己的时序、CDC、DRC 与约束审查。
