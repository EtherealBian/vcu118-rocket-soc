# 四路 BOOM 的整数发射选择器：保持 40 槽，不加流水级

**实验问题：** 单 hart 四路 BOOM 的整数发射器能否在不改变发射顺序、队列容量和停顿行为的前提下，减少组合选择逻辑？这里比较的是同一个 RTL 模块的四种实现，不是四个 CPU，也不是九级 Rocket。**目前没有由这项改动得到的上板成绩或时钟频率。**

## 仅改一个模块

- **优先级选择（grant）**：原版按从老到新的槽顺序分配可用端口。候选按端口优先级依次选最老的合格槽，把 40 个槽分为 5 组、每组 8 个，已被前序端口取走的槽不再参选。160 个 grant 位必须逐位一致，不能只是每拍发射条数相等。
- **数据选择（payload）**：有 grant 时，按独热掩码取数后用平衡 OR 树合并；无 grant 时保留原来的空闲输出，包括 12 个非零默认字段。端口 0/1/2/3 分别有 394/136/136/136 位，共 159 个字段、802 位。
- **不动的部分**：发射槽存储、唤醒、压缩、流水寄存器、ROB、时钟、顶层和约束均保持不变。封存的两个候选与原物理输入各有 549 个有序 HDL 文件；对 589 项清单逐项比较，只允许 `rtl/IssueUnitCollapsing_2.sv` 的内容变化。原件继续独立实现；派生包内沿用的模型记录不能当作候选的验证。

## 等价性如何复核

从锁定的原版 SystemVerilog 中抽取 622 条真实的仲裁语句。对任意二值输入，先证明每个端口的 40 位 grant 至多一位置一，再按端口 0→3 归纳证明分组候选与原版一致。数据侧核对每个字段的槽号、grant、位宽和默认值；在至多一个 grant 的前提下，分别证明空闲输出为 0 和为 1 的逐位选择式。故意制造多 grant、取错数据位、遗漏最老槽三种错误，均得到反例。**这是组合二值证明，不是四态仿真、整核启动或物理时序签核。** [求解器记录、原件与候选指纹](perf-mega175-issue-input.json)。

## 同一接口下的技术映射

输入为各槽的独立请求和数据；同一个 `fu_code` 同时送仲裁和数据选择，不复制成两套独立输入。输出为 40 个槽确认位、4 个端口有效位，再加选定的数据位。使用相同版 Yosys/ABC、`synth_xilinx -family xcup -flatten` 和相同引脚比较。表格每格为 **映射原语数 / 最长路径的组合原语层数**。层数按每个 LUT、MUX 等权计数，不是 ns。两列的输出接口不同，**只在同一列内比较**。

| 选择器 | 36 位（各端口的 `uopc`、`dst_rtype`） | 全部 802 位 |
| --- | ---: | ---: |
| 原版 | 3,281 / 37 | 26,840 / 35 |
| 只换数据选择 | 3,343 / 31 | 25,619 / 33 |
| 只换分组仲裁 | 3,380 / 32 | 24,256 / 32 |
| 同时替换两者 | 3,189 / 30 | 27,849 / 31 |

完整接口改变了选择：只换仲裁比原版少 2,584 个原语，最长路径少 3 层；两者都换时最长路径再少 1 层，却比原版多 1,009 个原语。36 位子集上“两者都换”同时最小、最浅的结论，不能推广到整个输出。分别封存只换仲裁和两者都换的输入，暂不替换正在实现的原版。

[36 位映射明细](perf-mega175-issue-map-36.json) · [802 位映射明细](perf-mega175-issue-map-802.json)。映射只包含仲裁和输出选择，不含槽存储、真实扇出布线、下游裁剪和整核放置。下一步先查原版**布线后**的寄存器端点和单元/走线延时占比；只有路径证据支持，才值得安排独立候选做相同约束的物理比较。不能把原语层数换算成 Fmax 或 CoreMark。

## 布线后怎么决定是否换仲裁器

原版四路构建退出并写出最终 `post_route.dcp` 和端点报告后，运行 `python3 scripts/review-mega-data-hops.py "$run" "$kit" "$vivado_log"`。工具先核对构建指纹、40 个端点和 8 条详细路径（setup、hold 各一组），然后逐段核对详细路径的单元、走线和累计延时。它列出每条数据路径最慢的三段走线、这些走线连的是哪两个引脚，以及不同端点反复经过的同一段。时钟树上的跨 SLR 记录不计作数据线跨区。

如果慢段集中在发射器之前，仅凭终点落在发射槽就替换仲裁器，可能改不到关键逻辑。如果同一仲裁数据通路反复出现在违例的 setup 路径上，再用相同约束构建对应候选。某段走线的延时不是改动后可以全部收回的时间；这项分析不能代替整机时序、CDC 或板测。

## 复现

从[四路实现输入清单](perf-mega175-implementation-inputs.json)对应的私有重建包开始；不需要 JTAG。命令使用同一 Yosys 及其调用的 `berkeley-abc`，映射 JSON 中有可执行文件哈希。输出目录必须不存在。

```sh
python3 scripts/derive-mega-issue-input.py "$kit" "$out/candidate-check" --yosys "$yosys"
python3 scripts/map-mega-issue-cut.py "$kit" "$out/cut-36" --yosys "$yosys"
python3 scripts/map-mega-issue-cut.py "$kit" "$out/cut-802" --yosys "$yosys" --full-payload
```

第一条会重新求解正、负用例，再组合两种修改，检查两种组合次序得到同一份字节，分别在 `grouped_grants` 和 `both` 中封存两个候选。三条命令都不运行 Vivado、不访问板卡。公开记录不包含生成的第三方 HDL、主机绝对路径或线缆标识。
