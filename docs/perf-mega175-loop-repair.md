# 把循环预测器的修复命中提前一拍

针对[原四路布局布线中的次慢路径](perf-mega175-routed-recovery.md)：循环预测器的 F3 请求索引经修复旁路、方向预测、历史选择到指令缓存地址，建立余量 −9.230 ns。这一源寄存器覆盖最差 40 个 CPU 端点中的 19 个。这里做的是**同周期行为不变的 RTL 候选**，不改时钟、预测算法、CoreMark、板卡配置或原构建。

### 为什么能提前？

原四列各自把 36 位 `s2_idx` 写入 F3 寄存器；同一上升沿，父模块也采入更新地址 `io_update_bits_pc[39:4]`、更新有效位、修复标志和列掩码。原设计在该沿**之后**比较两个已寄存的地址，决定对各列旁路 10 位计数还是用表中读出的值。候选在沿**之前**比较这两个 D 输入，同一沿锁存 4 个逐列使能，在 F3 用它们选同样的数据。不延迟取指，也不删掉 F2 或训练路径仍需要的地址比较。代价是把比较移到了上一级；若更新地址到达过晚，收益可能抵消。

### 做过哪些验证？

- **整组四列，二态 SAT。** 从同一物理输入清单取得实际的 Bank 和 Column。展开后每个时钟都是同一个上升沿。把 407 个共有寄存器的 3,239 个状态位一一配对；剩余的参考状态是每列 36 位原索引，候选是 4 位旁路使能。给定任意对应状态（每位使能等于参考那一列的修复条件），对任意外部输入证明：648 位输出相同、全部共有下一状态相同，且下一拍仍满足对应关系。全零状态满足起始关系；不假定各个未初始化寄存器可以独立随机而仍然对应。这是 RTL 行为证明，不是实现后的触发器节省量。
- **原始 SystemVerilog 四态对照。** 2,304 个时钟沿；复位预热后从第 26 沿起核对，每轮沿前、沿后均比较全部输出，参考出现未知值即失败。覆盖 16 种列掩码、36 个单比特地址差异、472 次 F3 未接收但有修复旁路、634 次修复与误判更新重合；实际观察到四列都反转过输入预测，共 92 个 lane 样本。这里比较的是完整模块，不是用 Python 公式代替 DUT。
- **负对照。** 只让候选忽略地址位 35，SAT 找到反例，四态测试也在 `t=51` 报告外部输出不一致。没有把未证明或未覆盖算作通过。

[去敏结果、模块与工具指纹](perf-mega175-loop-repair.json)。旧 Yosys 不接受原五处二维 packed net；仅在形式验证输入中用显式顺序的拼接重写其声明及连线，原 RHS 不变。四态仿真、物理对照使用未经这种改写的 SV。

### 复现

```sh
python3 scripts/test-mega-loop-repair.py "$KIT" "$FRESH_PROOF" \
  --yosys "$YOSYS" --iverilog "$IVERILOG" --vvp "$VVP" --ivl-dir "$IVL_DIR"
python3 scripts/prepare-mega-loop-ooc.py "$KIT" "$FRESH_PROOF/result.json" "$FRESH_PAIR"
vivado -mode batch -source scripts/implement-mega-loop-ooc.tcl -tclargs "$FRESH_PAIR" "$FRESH_IMPL"
```

第三步在同一 `xcvu9p-flga2104-2L-e` 上串行实现原版与候选。全部 bank 输入（时钟除外）和输出在同一外壳寄存，只在边界寄存器加保留属性。时钟周期 5.714 ns。检查各列到预测方向输出寄存器、全组最差寄存器路径及候选提前一级后的四个使能 D 脚。这不是整机：没有真实 F3 后方的历史选择、I-cache 地址、跨 SLR 的布局及布线竞争。即使本地通过也不能签核 175 MHz 或换算 CoreMark。

### 11 月 28 日：同约束的两次局部布局布线已完成

Vivado 2024.2 正常退出，原版 4,886 个、候选 5,269 个可布网络全部布完，均无布线错误。两边各一次，不是多次布局的统计。结果是**四条 F3 方向输出都变快，但整个预测器最坏建立余量只多出 0.046 ns，而且用了更多 LUT**。

| 同一寄存边界，单位 ns | 原版 | 候选 |
|---|---:|---:|
| 列 0：到 F3 `taken` 的建立余量 | +2.722 | +3.627 |
| 列 1 | +2.785 | +3.773 |
| 列 2 | +2.378 | +3.759 |
| 列 3 | +2.702 | +3.483 |
| 全模块 WNS / WHS | +1.885 / +0.045 | +1.931 / +0.043 |
| CLB LUT / 寄存器（含相同外壳） | 2,753 / 4,182 | 3,078 / 4,191 |

四列最坏的数据路径均由 7 层降至 4 层。候选起点均为本列的新使能 Q；原版起点为更新地址寄存器。四列中最差余量由 +2.378 到 +3.483 ns（两版最差列不同）。全组最坏路径已从 F2 索引到 F3 计数寄存器的 D，移到更新索引到预测表项的 CE；两边均未使用块 RAM 或 DSP。**不能把 1.105 ns 直接加到原整机的 −9.230 ns 上**，也不能把原设计的 144 个形式状态位当作物理节省的触发器。

对新使能的 4 个 D 脚，报告给出的起点都是已寄存的列掩码，数据路为直连。D 脚的 +5.337 至 +5.413 ns **不是**地址比较余量；这次没有按使能触发器的全部控制脚单独提取比较路径。全模块 WNS 已包含实际有时序检查的寄存器控制脚。外壳没有外部 I/O delay；这里只比较寄存器之间的路径。决定：保留这个前端候选供整机对照，不单凭它重跑原版后处理或上板；后端同样慢的 miss → 发射槽路径必须一起评估。
