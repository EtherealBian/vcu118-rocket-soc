# 四路 BOOM：分支误判掩码要不要提前译码？

**暂不换主线。** 现有实现的布局后物理优化多次处理分支标签和 `valid` 网，其中一些驱动被复制。这说明值得检查分支广播，但不能证明最终慢路径经过标签译码。用[同一份四路物理输入](perf-mega175-implementation-inputs.json)比较四种 RTL 后，只把 `decode` 封存为备选：它把误判掩码的寄存器后组合深度从 3–4 层减到 2 层，代价是寄存器前的标签路径增加 1 层、切面多 80 个触发器。没有给 CPU 增加一级流水，也没有新的板测成绩。

## 改了哪条路径？

四个执行槽分别给出 5 位分支标签、有效位和误判位。原版在同一个上升沿采样；若 ROB 此时要求 flush，该槽采入的有效位为零。随后把各标签变成 20 位掩码并合并：`resolve` 标出哪些分支得到了结果，`mispredict` 标出其中哪些预测错了。标签 20–31 在这个切面不置位。四个槽原有的 28 位二进制读出在所有版本中保留，其他消费者不被迫改用独热码。

下表对比的是**孤立切面映射网表**。输入列按 `tag / valid / miss / flush` 分列，是相应输入到任一触发器 D 的最大组合原语层数。输出列是触发器 Q 到每条掩码最远的组合层数；直连计 0，触发器本身不计层。LUT 数为 LUT1–6 实例合计，MUXF 单列，不是实际占用的 FPGA 站点。

| 同沿采样方案 | 输入 → D | Q → resolve | Q → mispredict | FF | LUT | MUXF |
|---|---|---:|---:|---:|---:|---:|
| 原版：寄存二进制标签 | 0 / 1 / 0 / 1 | 2 | 16 位为 3，4 位为 4 | 28 | 201 | 44 |
| `decode`：另存完整独热标签，沿后按有效/误判门控 | 1 / 1 / 0 / 1 | 2 | 2 | 108 | 190 | 0 |
| `qualified`：沿前连有效/误判一起计算，另存两张掩码 | 3 / 3 / 3 / 3 | 1 | 1 | 188 | 524 | 320 |
| `banked`：寄存 5 个高组、4 个低位及 4 个带误判的低位 | 1 / 1 / 1 / 1 | 3 | 3 | 80 | 216 | 120 |

`qualified` 的确把沿后降到 1 层，但这个具体的移位写法把代价转给了执行槽和 flush 输入。`banked` 少用独热寄存器，却让原来 2 层的 resolve 变成 3 层。在本次映射中，`decode` 是优先复核的折中；**原版对标签输入本身仍是直连**。等权的原语层数不含布线、负载、打包和时钟树，没有 ns 或 MHz 的含义。表中不是四个完整 BOOM 的面积。

## 已验证什么？

- 从四份完整 `BoomCore` 文本实际抽取有效、误判、标签的同沿寄存及 B1 掩码表达式。任意两态输入、任意先验寄存器状态下，用 Yosys SAT 比较 68 位输出（两张 20 位掩码和 28 位原始读出）：三个变体在第一个共同采样沿之后均与原版一致。被比较的寄存器每拍无条件重写且无反馈，因此不依赖更早历史。这个检查**不覆盖**第一个沿之前的 FPGA INIT、四态 X 传播、其他整核行为或母板时序。
- 三项负控各改坏一个实际采样式：遗漏 flush、接错槽位、误用上一拍标签。三项均在相同检查时刻得到不相等的反例，超时或工具失败不算检测到反例。
- 单独将完整原版和 `decode` 的 `BoomCore` 与源自封存 RTL 的 **19 种直接子模块接口 / 23 个实例** 做端口和语法检查，子模块体置空。Verilator 分别启用 `SYNTHESIS` 和 `RANDOMIZE_REG_INIT`；每种模式两边各有原有的 9 条 `WIDTHEXPAND`，消息一致。没有把接口检查当作子模块行为仿真。
- `decode` 的独立封存包为 `69422cdaccbd17776782930314ef6f0bdecebc0cc9f0895a65cb666649b840a7`。589 个清单成员中只有 `rtl/BoomCore.sv` 内容改变；549 个 HDL 的编译顺序、PLL、MIG、时钟和板级约束均未改。包内继承的旧模型收据只属于原版。两次独立生成的[脱敏结果 JSON](perf-mega175-branch-mask.json)逐字节一致。

## 何时值得另开物理构建？

等待原版的 `post_route.dcp` 及[同一构建的分段路径审查](perf-mega175-issue.md)。如果不同的违例端点前**反复出现从 B1 标签寄存器、经过误判掩码译码的慢段**，再检查前一拍标签产生路径的余量；两者都支持这个切分时，才用相同约束实现 `decode` 作对照。若慢段来自另一路 ROB/B2 二进制读出、译码以后的广播走线或其他跨 SLR 路径，仅复制独热标签未必缩短它。候选没有做整机布局布线，不替代主线，也不能据此推算 CoreMark。

## 复核命令

准备上述原版封存包、Yosys 0.9 `1979e0b`、其 `berkeley-abc` 及 Verilator 5.022。使用对应到这套安装的库环境（如有需要，设置 `VERILATOR_ROOT` 为含 `include/` 的目录）。命令不访问板卡、不运行 Vivado；新目录须不存在。完整生成 RTL、检查网表、日志和封存包只留本地。

```sh
python3 scripts/test-mega-branch-cut.py "$kit" "$private/b1-a" --yosys "$yosys" --verilator "$verilator_bin"
python3 scripts/test-mega-branch-cut.py "$kit" "$private/b1-b" --yosys "$yosys" --verilator "$verilator_bin"
cmp "$private/b1-a/summary.json" "$private/b1-b/summary.json"
```
