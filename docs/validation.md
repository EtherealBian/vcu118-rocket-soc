## 调试总线缓冲与跨时钟复查

- 生成的调试从设备 A（请求）和 D（响应）各有一个两项队列。在该 RTL 上独立改变两端的 ready/valid，共 4,112 拍：A 接收 2,611 项、交付 2,607 项，D 接收 1,955 项、交付 1,951 项；每个方向还有 4 项由两次满队列复位明确丢弃。逐拍核对已阻塞的首项、消费顺序与结束时的空队列。
- 同一候选的完整 ChipTop 通过 SBA 回包测试；坏魔数、超长、CRC 错误三例均读回预期停机地址。**这些是 RTL 测试，不是实板。** 100 MHz 的完整实现仍按布线后的数据判定。
- 对 ROM4 的全部 580 行 CDC 明细逐条与汇总计数对账，9 行 Critical 涉及复位整形器、调试与 DDR 异步队列、dmactive 双接收和调试中断。仅检查同步器单模块会漏掉问题：未标属性时，单模块能综合成三个触发器，整机却变成一个 FDRE 和一个 SRL16E。给缓冲候选的该同步器加属性后，整机综合网表确认为三个带 ASYNC_REG 的 FDRE，两级中间连接均只有一个后继。
- **尚未解决的细节**：第一级 D 的实际驱动是 LUT2（真值表 `4'hE`），把 JTCK 域的普通停核请求和系统时钟域的复位停核请求相或。移除 SRL 不等于移除了这个跨域组合路径。没有因此新增时序豁免或批准下载。
- 128 MiB 诊断 Linux 的 RTL 串口已报告 125,148 KiB 可用、PLIC 两个上下文、100 kHz 的 sched_clock；默认 2 GiB 内核在第 8,000 万和 1 亿拍的停核样本分别位于 `__free_pages_ok` 和 `__free_pages_core`。这是内核执行进展，不是用户态自检或实板启动记录。

## 调试访存与停核请求实测（RTL）

- 在时钟对照版和带两项缓冲的版本上，分别用 JTAG 停核，让 hart 通过程序缓冲区访问调试数据区，再从独立 DMI 口读回。两版各完成 180 次写、180 次读，涵盖 32 字节数据区内全部对齐位置和 1/2/4/8 字节宽度，也验证未写入的字节保持原值。每版 7,688,092 拍；停核前有一次 ROM 栈的 64 字节写分配读，测试期间无额外外存访问、无 SD 命令。
- 新增一个独立候选：JTCK 发起的停核和本地复位停核各经过两级寄存，随后才在调试时钟域相或。原 tile 的三级接收器保留，因此多两个接收时钟边沿。这不是处理器流水级的变化。
- 在两版真实生成的调试模块中用公开 DMI 接口各测 9 种时钟比/相位组合，覆盖普通停核、复位停核屏蔽/使能、复位记录清除和两路停核重叠后的两种撤销顺序。将原模块输出在目标时钟延迟两拍后，与新版本的引脚和握手逐事件比较：110,205 个事件全部相符，其中 536 个事件与未延迟输出不同。这里由测试台驱动 hart 复位状态，不能据此宣称板级复位接线或亚稳态可靠性已验证。
- 这一候选的完整 ChipTop 也通过了 SBA 上传、裸机回包和相同的 180 写/180 读矩阵，仍需整机综合网表复核、布线后时序和实板测试。具体命令见重建指南。

- 在时钟对照版的板级 `ResetWrangler` 真实生成 RTL 上，分别驱动系统和 MIG 两侧的复位原因与独立时钟，验证了双因重叠、接近门限的短暂重置、任意一侧时钟停止及恢复。9 组时钟比/相位各逐事件核对 367,174 次；每个输出在各自的时钟边沿释放 4 次。复位消抖计数需 10,000 个系统边沿，随后还有释放寄存器及各域三级复位链。此项**不**验证模拟亚稳、恢复/移除时序、MIG 校准或实板 DDR。

两个版本的全设计最差建立路径都在 DDR UI 校准逻辑，三类时序均为零失败端点。缓冲版仍有 7 条 Critical CDC、59 条路由后 DRC Warning；仅凭 STA 不批准下载；下文记录完成板级复核后的限定实验。其 J4 UART RX 的路由网表确认：原始输入只接两级同步器的第一级，两级均为带属性的 FDRE、位于同一 slice；级间无组合逻辑，数据延迟 0.302 ns，建立裕量 +9.580 ns。TX 只有一个 100 MHz 寄存器发起。两版完整 ChipTop 的 UART 裸机上传各用 13,049,856 拍，均观察到 handoff 和两轮 1 MiB 自检；这是仿真 RAM，不是板上内存。

- **封装与板卡对照：** 对两份路由后网表，按逻辑名、位号、极性、封装球位、bank、使用类型、I/O 标准和锁定状态检查了 133/133 个端口。MIG 的 `ddr_c0_ddr4_*` 是 IP 实例命名，115 根实际连到板上 **C1** 的 banks 71/72/73，使用 64 位数据、8 对 DQS，对应 U60–U63 的数据字节。板上 C1 物理总线为 80 位，未把多出的 16 位算入可用内存。板定义与 UG1224 的连接核对不能测出供电或 DDR 校准结果。
- **板级内存适配器 RTL：** 对时钟对照版和停核拆分版各测 12 组系统/UI 时钟比及相位，两端分别计分，只有厂商 MIG 被 AXI RAM 模型替换。每组观察到 AW/W/B/AR/R 握手 128/480/128/128/480 次、608 个 TileLink 响应拍、最多 8 个挂起请求。两例故障（高地址镜像、忽略写掩码）均在读回数据时被拒绝。未测试 DDR 引脚上的波形或芯片。
- **被忽略路径盘点：** 时钟对照版对同一最终 DCP 的 100→200 MHz、200→100 MHz 两个方向，各取每个端点的一条 max 和 min 路径，与时钟交互报告对出 188、118 个端点。正向 155 个数据、20 个 Gray 指针、13 个有效/复位端点；反向 73、20、25 个。数据 / Gray 的 max 报告最大数据延迟分别为 1.436 / 1.250 ns 和 1.353 / 1.137 ns。它们不是有约束路径的裕量；已有四项 bus-skew 检查均属调试 hub，不能代替此 AXI 桥。两条 TIMING-47 未豁免。

## 接线与自动测试

配置 FPGA 用 **J106** 的 USB-JTAG；它不是软核调试 TAP（后者在 FMC_J2）。USB-UART 用 **J4**：CP2105 **Standard** 是软核控制台；Enhanced 接板管，不发送测试命令。板载管理 microSD 不接 XCVU9P。使用 SD 启动时，J52 PMOD 侧需单独的 3.3 V SPI SDHC 模块；按板上标号核对 J52.1 = CS_n、J52.3 = MOSI、J52.5 = MISO、J52.7 = SCLK，另接电源和公共地。板卡参考：AMD *VCU118 Evaluation Board User Guide* (UG1224)，USB、SD 与 PMOD 章节。

先用 `scripts/probe_board.tcl` 枚举，用 `scripts/identify-board.tcl` 只读核对线缆和器件。Windows 预检：`./scripts/test-connected-board.ps1 -Bridge <USB串口芯片序列号>`，默认不编程。确定目标与引脚、人工审查完整布线时序/CDC/DRC 后，显式传入 `-Program -Mode bare` 或 `linux`、`-Run <实现目录>`、`-ReviewedBitSha256 <已审核bit哈希>`、`-Bridge`、`-Cable`、`-Slr0Dna`。脚本先开正确的串口，再核对片上身份，易失编程，核对三片 SLR 配置状态，最后核验诊断输出或随机 shell 挑战。不写 Flash 或 SD；选用适合当前模式且已准备的启动介质。所有物理标识、日志和镜像均保留在本机。

## 首次 Rocket 实板读写 · 15:39–15:40（上海时间）

## 实板 Linux shell · 15:49（上海时间）

同一缓冲版重新易失配置后，600 B ROM 从 J4 接收 5,341,704 B 完整基线固件，收到 `UART5_HANDOFF`。随后实板串口依次出现 OpenSBI v1.5、Linux 6.6.65、`VCU118_INITRAMFS_READY`、`SOC_CHECK_PASS bytes=16777216 passes=1 elapsed_s=2` 和 BusyBox v1.36.1 的 `ash`。主机在看到提示符后发送含新随机串的算术命令；验收器要求出现带同一随机串的**展开结果**，不接受回显的命令。独立脚本再从本轮 bit、路由报告、JTAG 读回、发送帧和 UART 记录重算通过。

这是使用板载 DDR 的串口启动，不是仿真预载或 SD 启动。系统运行在 RAM，断电不保留；没有写入 Flash 或 SD。基线 initramfs 为实验室本地控制台，不提供远程登录；本次不代表生产系统加固或全部外设签核。

## 三个候选的证据不要混用

- **停核拆分版（不含 Dot4）**：113,460 个可布线网络全部完成。全设计建立/保持/脉宽为 +0.822 / +0.010 / +0.143 ns，100 MHz 同域最差建立裕量 +1.063 ns。59,971 LUT、42,510 FF、203.5 BRAM、28 DSP。最终网表确认先分别寄存再合并停核信号；仍有 6 条 Critical CDC（DMI、DDR 异步队列有效位复位及 MIG/POR，每类 2 条）、2 项 TIMING-47、58 条 DRC Warning。不是整机 CDC 签核。独立易失重配后，裸机 1 MiB、四窗强制刷出、三类计数器循环均再次通过；只读 MIG 报告 CAL PASS（12 PASS / 15 SKIP）。逐项证据在 `physical.split_halt_soc`。
- **带调试缓冲的 Dot4 版**：用 UART 引脚把 896 B 裸机程序从 ROM5 送入 Rocket；未预载 RAM，未用调试口交接，未发 SD 命令。257 组 INT8 点积和两项非法命令检查通过。共 8,812,544 拍，外部 TL 17 读、0 写；记入 `dot4.buffered_uart_rtl`。这是仿真，并非 DDR 或加速比测试。
- **可选 Linux 双进程测试**：独立构建的镜像通过 QEMU virt 的完整启动、自检和 shell。两个进程 fork 后分别校验同一虚拟页的不同私有内容；使用共享匿名映射做 128 次 `amoadd.d.aqrl`，在双向管道交换期间保持并分别检查单、双精度寄存器。三个负例独立破坏 FPR、一个页字节或 AMO 操作，退出码均为 5，未打印通过标志。这些是单核结果，不证明多核一致性。
