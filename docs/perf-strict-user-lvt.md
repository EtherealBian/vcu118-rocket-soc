# 换寄存器堆后，四路 BOOM 的热区多花了几拍？

**这个样本里，每轮相差 0 拍。** 把四路 BOOM 的整数和浮点寄存器堆换成按写口分银行、用标签选最新值的 LVT 后，两个 RTL 模型分别重放同一严格对齐 ELF 的性能、验证两段快照。每段四轮，单 hart、单上下文、标准 2,000 字节。下表是**模型时钟周期**，不是 VCU118 的 CoreMark 次/秒。

| 种子 | 原版与 LVT：第 1 / 2 / 3 / 4 轮周期 | LVT − 原版（逐轮） | 两者有序提交的热区指令数 |
|---|---|---|---:|
| 性能 | 171,404 / 161,746 / 160,691 / 159,606 | 0 / 0 / 0 / 0 | 1,347,261 |
| 验证 | 173,150 / 162,949 / 161,180 / 160,257 | 0 / 0 / 0 / 0 | 1,348,735 |

**比较了什么。** 两个测试程序分别链接已封存的原版和 LVT 整核归档。每个种子的起始 RAM、24 字节 ROM 串口帧及测试代码相同；两种种子使用不同 RAM。逐字节比较两个模型的提交 PC 文件、串口输出和事件记录。两套模型的完整 PC 顺序也都通过独立模拟器参考序列的校验，并在核对 32 个通用寄存器槽、3,120 字节可写段、1,728 字节栈和 2,000 字节堆后各自输出 `K`。[重放方法与局限](perf-strict-user-replay.md) · [两套归档、输入和观测摘要](perf-strict-user-lvt.json)。这里没有逐拍比较所有内部信号，也不是对任意程序的整核等价证明。

**还有多少拍没有提交？** 从 MRET 到用户 ECALL 陷入，性能种子的 653,686 拍中有 122,682 拍零提交（18.77%），有 206,084 拍提交四条（31.53%）；原版与 LVT 相同。这个统计窗口比表中四轮热区略长，不能用它把空拍归因给寄存器堆、分支预测或存储系统。

**实现取舍。** 这次替换没有减少已测热区的拍数。只有当原版最终布线显示慢路径反复经过寄存器堆时，才值得用 LVT 对比同频时序、资源和拥塞。候选的 Windows 实现输入已单独复核：550 个有序 HDL 文件，相对原版 549 个，仅两份 RAM 封装、新 LVT 模块和文件清单不同；时钟、板级约束、MIG 和实现 Tcl 未变。[两套物理输入的封存差异](perf-mega175-regfile-input.json)。本次未为候选启动 Vivado，也没有得到新板分。

## 离线复核

先按[快照重放步骤](perf-strict-user-replay.md#离线复核)准备两个种子的客体快照。对同一份 `guest` 串行运行下列命令；两个输出目录须尚不存在。`STOCK_KIT` 和 `LVT_KIT` 在这里指各自 Verilator 归档所对应的目录，不能用原版板级目录代替原版功能模型目录。配对审查从两边的原始输入、事件、PC 和 UART 重算，不是比较两个输出 JSON。

```sh
bash scripts/test-strict-user-replay.sh "$STOCK_KIT" "$STOCK_OBJ" "$PRIVATE/guest" "$PRIVATE/stock" stock
bash scripts/test-strict-user-replay.sh "$LVT_KIT" "$LVT_OBJ" "$PRIVATE/guest" "$PRIVATE/lvt" lvt
python3 scripts/review-strict-replay-pair.py "$STOCK_KIT" "$STOCK_OBJ" "$PRIVATE/stock" \
  "$LVT_KIT" "$LVT_OBJ" "$PRIVATE/lvt" "$PRIVATE/guest"
```

反向核对：用真实原版模型目录却指定 `lvt`，程序在链接之前就拒绝了错误的来源；单元测试还覆盖输入被改写、两次复用同一可执行文件，以及只移动一个轮次边界一拍。
